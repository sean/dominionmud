# AGENTS.md — DominionMUD

Guidance for AI coding agents (and humans) working on this repository.
Read this file first; it was written by checking the documentation against the
actual source, building it, and booting the server (gcc 13 / Linux, October 2026).

---

## 1. What this project is

- **The Dominion** is a multi-user dungeon (MUD) server written in C between
  1993 and 1998 by Sean Mountcastle (in-game "Glasgian"), Kevin Huff and John Olvey.
  It was recovered from a backup in 2015 and patched to build on Mac OS X 10.10.
- It is a heavily modified **CircleMUD 3.0** (itself derived from **DikuMUD**).
  It also includes **Merc-style MOBprograms** (`mobprog.c`, `mobcmd.c`), an
  OLC (on-line creation) editor (`creation.c`, `olc.c`), copyover (hot reboot),
  data-driven races/religions/guilds/experience tables, and plain-text player files (one per character).
- Upstream remote: `https://github.com/sean/dominionmud` (branch `master`, 4 commits from 2015).
- **License:** `LICENSE.md` (Dominion license + CircleMUD + DikuMUD licenses). Keep every
  existing copyright/credit header, never remove the CircleMUD/DikuMUD credits, and
  leave the in-game `credits` text (`lib/text/credits`) attributing the original authors.

Most CircleMUD 3.0 knowledge applies directly. When the CircleMUD idiom and this
file disagree, the **source code wins**.

## 2. Source of truth: read this before trusting documentation; source code is always authoritative

Rules for agents:
- **Verify any API, macro or file name in the source** (`grep`) before using it. Never copy a
  code sample from documentation without checking it.
- Keep sources plain ASCII. Write any non-ASCII byte as an escape (e.g. the CP437 bar-graphic
  characters in `act_info.c` are `"\xb0"` / `"\xb2"`); raw high bytes make clang warn and make `grep`
  treat the file as binary.
- If you find a doc error while working in an area, fix it or flag it in your summary.
  Don't do big doc rewrites unless asked.
- Authoritative in-repo references are the code itself, especially `structs.h`, `utils.h`,
  `interpre.c`, `spells.h`, `spell_pa.c`, `db.h` and the comments at the top of each `lib/data/*` file.

## 4. Build, run and smoke-test

### Build
```sh
make                 # from repo root → builds bin/dominion (via src/Makefile)
cd src && make utils # optional: autowiz listrent purgeplay showplay sign split
make clean
```
- `mkdir -p bin` first on a fresh checkout if needed. `bin/dominion` is gitignored.
- The committed `src/Makefile` and `src/conf.h` are **configure outputs** (from a 2015 macOS run).
  Edit `Makefile.in` / `conf.h.in` too when you change them, or both drift. Running `./configure`
  regenerates them. Don't commit platform-specific regenerated output without saying so.
- **Do not run `make realclean`**: it deletes `lib/etc/plrmail` (player mail).
- **Baseline: zero warnings** with gcc 13.3 and 11.4 and clang 18 at `-Wall` (Linux x86-64), for both
  `make` and the utilities. **Keep it at zero: a change must not add any warning.** Check with a clean build:
  ```sh
  cd src && make clean >/dev/null && make 2>&1 | grep -c 'warning:'    # expect 0
  ```
  If you're on macOS, also check with clang (`make CC=clang`).
- Header dependencies are automatic. The compiler writes a `.d` file per object (`-MMD -MP`, which gcc
  and clang support), and the Makefile includes them, so editing any header rebuilds exactly the files
  that use it. Editing `src/Makefile` rebuilds everything. A plain `make` is enough; you only need
  `make clean` to start from scratch. `.d` files are gitignored and removed by `make clean`.

### Run
Run from the **repo root** (the default data dir is the relative path `lib`):
```sh
./bin/dominion [-m] [-q] [-r N] [-s] [-d libdir] [port]   # default port 8400
```
- `-m` mini-MUD (loads `index.mini` files, no rent check): fastest for testing
- `-q` quick boot (skip rent check) · `-s` no special procedures · `-r N` restrict new players
- `-c` syntax-check mode: loads all world and data files, then exits 0 if they parse. A fast check after data edits
- `-C<fd>` is internal (copyover re-exec)
- Logs go to stderr. On a healthy boot you get a run of `Resetting <zone>` lines and then
  `No connections.  Going to sleep.` A full boot of the stock world logs **no `SYSERR`s**, and neither
  does `dominion -c`. Zone resets still use random rolls, so a data bug may show up only on some boots:
  boot a few times after data changes and treat any `SYSERR` as a regression.
- `bin/nightrun.sh` (csh autorun loop) and `bin/automain.sh` are 1990s scripts. They expect a
  directory named `DominionMUD`, `lib/logs/` and a `debug/` dir. Treat them as historical, not as the dev workflow.

### Smoke test (do this after any change that touches runtime code or data)
```sh
./bin/dominion -q 8400 > /tmp/syslog 2>&1 &
sleep 5; grep -c SYSERR /tmp/syslog; tail -2 /tmp/syslog
python3 - <<'EOF'
import socket, time
s = socket.create_connection(("127.0.0.1", 8400)); s.settimeout(2)
def rd():
    out = b""
    try:
        while (d := s.recv(4096)): out += d
    except Exception: pass
    return out.decode("latin1")
print(rd()[-400:])
for line in ["n", "Testplayer"]:           # color prompt, then a new name
    s.sendall((line + "\r\n").encode()); time.sleep(0.5); print(rd()[-400:])
EOF
pkill dominion
```
Extend the script (password, race selection, commands) to exercise the feature you changed.
For combat, spells or saves, log in with a test character and use the actual commands.
**There is no automated test suite.** Proposing a small harness (e.g. a Python
telnet-script runner) is welcome. Ask before adding a framework.

Use `-g -O0` and/or `-fsanitize=address,undefined` (add them to `MYFLAGS` locally) plus `gdb` when debugging crashes.

## 5. How the code is put together (real patterns)

**Command handlers**
```c
ACMD(do_foo);                                   /* 1. prototype near top of interpre.c */
{ "foo", POS_RESTING, do_foo, 0, SCMD_FOO },    /* 2. row in cmd_info[] in interpre.c */
ACMD(do_foo) { ... }                            /* 3. body in the matching act_*.c */
```
- `cmd_info[]` row = `{ name, minimum_position, function, minimum_level, subcmd }`.
  `"RESERVED"` must stay first, the direction commands next, and `"\n"` last. The order of the main
  list matters for abbreviation matching (first prefix match wins), so put a new command where its
  abbreviations behave sensibly. `sort_commands()` builds a sorted index for display only.
- `SCMD_*` sub-command constants live in `interpre.h`. One function often serves several commands.
- Parse arguments with `one_argument()`, `two_arguments()`, `half_chop()`, `skip_spaces()`.

**Output and logging**
- `send_to_char(char *msg, struct char_data *ch)`: note the **message-first** order (CircleMUD 3.0,
  not tbaMUD). Not printf-style: format into a buffer first.
- `act(str, hide_invis, ch, obj, vict_obj, TO_CHAR|TO_VICT|TO_ROOM|TO_NOTVICT)` with `$n $N $e $m $s $p` codes.
- Global scratch buffers `buf`, `buf1`, `buf2`, `arg` (`MAX_STRING_LENGTH` = 64 KB) are shared by
  everything. Don't hold data in them across calls that might also use them. In new code, prefer
  local buffers and `snprintf`. Never `sprintf(buf, "%s...", buf)`: it's undefined behavior, and on modern
  glibc at `-O2` it wipes out the earlier text (this is why `score`/`stat` used to print one line).
  To append, use `sprintf(buf + strlen(buf), "...", ...)`.
- `SNPRINTF(dst, sizeof(dst), fmt, ...)` (`utils.h`) is `snprintf` that logs `SYSERR: message truncated`
  with the caller's file and line if the output didn't fit. Use it when building a message from other
  large buffers (e.g. copying `buf2` into `buf`).
- Every `fread`/`fgets`/`fscanf` must check its result. For boot-time data files, use
  `READ_CHECK(fscanf(fl, fmt, ...), expected_count, DATA_FILE)` or call `data_read_error()`. Either logs
  the data file and source line, then stops the boot, which is better than running with half-read data.
- `log()` is a macro for `mud_log()`. Use `mudlog(msg, BRF|NRM|CMP, level, TRUE)` for messages
  visible to immortals. Prefix real errors with `SYSERR:`.
- Colour via `CC*` macros in `screen.h` (`CCRED(ch, C_NRM)`, `CCNRM(...)`).

**World objects and memory**
- Characters and objects live on global linked lists (`character_list`, `object_list`) plus
  room/container/inventory lists. Move them only with `handler.c` functions (`char_to_room`/`char_from_room`,
  `obj_to_char`, `obj_to_room`, `equip_char`/`unequip_char`). Destroy them only with `extract_char` / `extract_obj`.
- Rooms are an array `world[]` indexed by **rnum**. Files and builders use **vnum**. Convert with
  `real_room()`, `real_mobile()`, `real_object()`. Mixing them up is the classic bug.
- Allocation uses `CREATE(ptr, type, n)` / `RECREATE` and `str_dup`.

**Spells and skills** (CircleMUD 3.0 design)
1. `#define SPELL_FOO n` in `spells.h` (spells 51…`MAX_SPELLS` 1200, skills to `MAX_SKILLS` 1700).
2. `spello(SPELL_FOO, max_mana, min_mana, mana_change, min_pos, targets, violent, routines)` in
   `mag_assign_spells()` (`spell_pa.c`). Routines are `MAG_DAMAGE | MAG_AFFECTS | ...`.
3. Implement the effect in the matching `mag_*()` switch in `magic.c` (`mag_damage`, `mag_affects`, ...),
   or as a manual `ASPELL(spell_foo)` in `spells.c` for unusual spells.
4. Add the name in the spell names table and the guild/class levels (see `spell_pa.c` / `guild.c`), plus a help entry in `lib/text/help/help.hlp`.

**Special procedures:** `SPECIAL(name)` in `spec_pro.c`, attached to mob, obj or room vnums in `spec_ass.c`.

**Timing:** `structs.h` `OPT_USEC 100000` gives 10 passes/sec. `PULSE_VIOLENCE` = 2 s, `PULSE_ZONE`/`PULSE_MOBILE` = 10 s, etc.

**Levels:** `MAX_LEVEL 50`. `LVL_IMMORT` 43 … `LVL_IMPL` 49, `LVL_CREATOR` 50. These are macros
like `MAX_LEVEL-7`, so wrap them in parentheses when you do arithmetic with them.

## 6. Data files

- `lib/data/{races,religions,guilds,exp_table,attributes}`: each file starts with a comment header
  that defines its format. Read it before editing. Parsers are in `race.c` (`parse_races`, `parse_experience`),
  `religion.c` and `guild.c`. Races are limited to 62 selector letters. `exp_table` needs one row per level up to `MAX_LEVEL`.
  `lib/etc/guilds` and `lib/data/guilds` are duplicates. Check `GUILD_FILE` in `db.h` (`data/guilds`)
  before deciding which one is live.
- World files use the standard CircleMUD 3.0 formats with Dominion extensions (races on mobs, "fuzzy" mobs,
  `>in_file_prog`). Add new zone files to the relevant `index` (and `index.mini` if they're needed in mini mode).
- MOBprograms (`lib/prog/*.prg`) use Merc 2.x syntax: `>greet_prog`, `>rand_prog`, `>speech_prog`,
  `>fight_prog`, `if ... endif`, `mpecho`, etc. `lib/prog/template.prg` documents the triggers.
- MOBprog gotchas (verified November 2026): a `>speech_prog`/`>act_prog` keyword list runs the prog once when
  any listed word is said (fixed in `mprog_wordlist_check`; it used to miss a later keyword such as `spheres`
  after a partial hit on `sphere`, and could run twice). A word or phrase matches only when followed by a
  space or the end of the line (`die.` does not match `p never die`). `mpechoat`, `mpforce` and
  `mptransfer` need the mob to *see* the player, so a mob that must work in a dark room needs infravision
  (affect flag `k`). `mptransfer` shows a moved player the room they arrive in. A `>give_prog` fires only when
  the given object's whole keyword list appears in the prog's argument.
- Puzzles: `lib/prog/pz_*.prg` drive the world's access+lore puzzles. Each uses a sentinel "fixture" mob
  (level 1, 30000 hp, no gold) loaded by its zone, and a hidden room reachable only through the prog, with a
  small reward loaded there by the zone reset. Solutions: say `death` at the skull in 10453 (Ancalador); say
  `scales` at the black monolith, 1154 (Mytherandil); ask the elven sage in 19043 about `runes`, then say
  `leaf` at the obelisk, 19008; give the torn scroll fragment from 32097 to the statue, 32095 (Serdim swamp);
  say `silence` to the chalk in 3752 (High Tower); say `we shall never die` at the Drerim archway, 1821;
  give 5 coins to the clockwork fish, 35003 (Gnishmire, lore only).
- OLC (`creation.c`) rewrites world files in place. If you hand-edit world files, keep the exact format
  OLC writes (tildes, `S` terminators, `$` at EOF) or the next OLC save may corrupt them.
- After any data change, run `./bin/dominion -c` (must exit 0 with no `SYSERR`), then boot the full world and look for new kinds of `SYSERR`.

## 7. Persistence (be careful: this is player data)

Each character is one text file, `lib/players/<first letter>/<name in lower case>`, written by
`pfile.c` (format described in `pfile.h`): `Key value` lines starting with `Version 1`, strings on one
line with `\n`/`\\` escapes. Readers skip unknown keys and leave missing ones zero, so **add a field by
adding a key** to `pfile_write`/`pfile_read`; no conversion is needed, and the files don't depend on
compiler, CPU or struct layout. Saves go to `<name>.new` and are renamed into place.
- `struct char_file_u` is now only an in-memory staging area between a file and `struct char_data`
  (`char_to_store`/`store_to_char` in `db.c`); its old "DO NOT CHANGE" comments no longer apply.
- `save.c`: `build_player_index()` reads every file at boot (creating the folders if missing) into
  `player_table` (name, id); `load_char()` reads one file, `save_char()` saves a playing character,
  `save_char_file()` writes a staged record (used by `set file`, guild accept/reject/dismiss).
- Names are matched exactly (`find_name`, `get_id_by_name`); they used to match abbreviations, so a
  new player typing a prefix of an existing name was offered that character's password prompt.
- The old binary `lib/etc/players` is no longer read or written. There were no player files to convert
  (the game hasn't run since 1997), so there is no converter.
- Utilities read the same files: `bin/showplay lib/players`, `bin/purgeplay [-d] lib/players`
  (lists, or with `-d` deletes, idle/deleted characters), `bin/autowiz`.

**Passwords** are never stored. `password.c` hashes them with PBKDF2-HMAC-SHA256 (16-byte random salt,
`PASSWORD_ROUNDS` = 100000) into `$pbkdf2-sha256$<rounds>$<salt>$<hash>`, the same format as Python's
passlib, in the 128-byte `pwd` field (`PWD_HASH_LENGTH`). Always use `password_hash()` and
`password_verify()` (`password.h`); never compare or copy passwords yourself. `password_verify()` also
accepts an old plaintext password and returns `PASSWORD_OK_REHASH`, and the login code then stores a
hash. The same happens for hashes with fewer rounds than `PASSWORD_ROUNDS`, so raising that constant
upgrades players as they log in. Each check costs about 0.1 s of CPU inside the single-threaded game
loop (more rounds means more lag per login). Typed passwords may be 3–`MAX_PWD_LENGTH` (64) characters.
Forgotten passwords can't be recovered, only reset: offline with `bin/mudpasswd lib/players <name>
<new-password>` (server stopped), or in-game by the implementor with `set <player> passwd <new>`.
`password.c` uses only the standard C library, so the utilities can link it too.

Object rent and crash files live in `lib/plrobjs` (`objsave.c`). Mail is in `lib/etc/plrmail` (binary).
Gitignored runtime files: `lib/players/`, `lib/etc/plrmail`, `lib/etc/mudtime`, `*.objs`, `*.alias`.

## 8. Known issues (verified October 2026; good starter tasks)

Security
- Simultaneous connections per IP address are capped (`max_conns_per_site` in `config.c`, default 5,
  0 = off). The *rate* of new connections isn't limited, though. A client can connect, try 3 passwords
  (about 0.3 s of game-loop time) and reconnect in a loop. A per-site rate limit or failed-login
  back-off would close that gap, and so would moving password hashing off the game loop.
- Every new connection does a blocking reverse-DNS lookup (`gethostbyaddr`) unless `slowns` is on.
- An implementor's `set <player> passwd <new>` echoes the new password back to them (not to the log).
- The server is IPv4-only (`AF_INET` sockets), and so is the per-site limit.
- Some `fscanf("%s")` calls have no field width (e.g. `ban.c`, copyover recovery in `comm.c`). The input
  files are local, but widths should be added.

Crashes and undefined behavior
- Fixed November 2026 (found with an AddressSanitizer build, `make CFLAGS="-g -O1 -fsanitize=address"
  LIBS=-fsanitize=address`, worth repeating after big changes): the clone spell freed the doppleganger
  prototype's strings (now gives the clone its own copies, scaled to the victim's level); `stat <mob>` on a
  mob with no race read `races[-1]` and crashed; `relg_name()` allowed an index one past the end; shops whose
  keeper mob doesn't exist wrote to `mob_index[-1]` at boot (now logged as "Shop #N disabled" and skipped;
  10 such shops, in zones 65, 120 and 150); `get_number()` ("2.guard") and three other places used
  overlapping `strcpy`; so did `half_chop()` (`set`). `stat file` read `world[]` with a load-room vnum.
  Loops over `player_table` stopped one player short (`<` instead of `<=`).
- Zone `temperature` (`weather.c`) is updated every hour but never read and never clamped. Nothing in
  the game uses it yet.
- Mob hit regeneration (`hit_gain()` via the shared `dummy_mob` `player_specials`) differs between `-O0`
  and `-O2` builds: `stat <mob>` shows `+0` at `-O2`. Something reads uninitialised or shared state.
- `FreeHates`/`FreeFears` (`mobact.c`) are never called, so a mob's hate/fear lists leak when it is extracted.

Housekeeping
- `castle.c` and `opinion.c` aren't built. `opinion.c`'s functions were partly moved into `mobact.c`, and
  its copies of `FreeHates`/`FreeFears` still have the old free-the-wrong-node bug.
- `src/util/Makefile` (generated from `src/util/Makefile.in`) is a separate legacy Makefile that the normal
  build doesn't use. The utilities are built by `src/Makefile`. It still has hand-listed header
  dependencies and targets for utilities that don't compile.
- Generated `src/Makefile`/`conf.h` are committed and macOS-flavoured. The legacy non-Unix Makefiles and
  `conf.h.*` are unmaintained.
- About 1,400 rooms are still unnamed placeholders ("Room NNNN", "This lovely room has yet to be written")
  in unfinished or unconnected areas.
- `TODO.md` (accounts system, skills/spells in text files), `lib/data/README`, and the 1990s player
  reports in `lib/misc/{bugs,ideas,typos,todo}` are the historical backlog.

Fixed in October 2026 (for history)
- `parse_fuzzy_mob()` used the prototype index instead of the race, giving fuzzy mobs garbage HP. `-c` mode
  didn't load the race tables and crashed. `FreeHates`/`FreeFears` freed the wrong node.
- All ~520 gcc warnings were cleared. Real bugs fixed along the way: overlapping `sprintf`s that wiped
  `score`/`stat`/`show` output; the `set` field list was never shown; good mobs used the neutral line
  (`IS_NEUTRAL(ch) < 250`); summon success messages used the failure table, which was also missing a comma;
  OLC wrote zone headers with a user-controlled format string and logged the wrong file name on open
  failure; `rent_adjust()` read an uninitialised struct; mob prototypes were `memset` with the pointer size;
  `save.c` stored pointers in `int`; `alias.c` read file-controlled lengths into a 127-byte buffer; boot
  hung forever on an index file with no `$` or a data file with no final newline; copyover recovery could
  spin on a truncated file; a short rent-file read could delete a player's crash file; and
  `file_to_string()`/`get_line()`/the ban list wrote before their buffers on a failed read.
- clang-only warnings, now also 0. **Gameplay change:** `IS_CARRYING_W` lacked parentheses, so carried
  weight (items, plus gold/100 for mortals) was always 0 and carry limits were never enforced. They are
  enforced now, so a mortal holding lots of gold can be over the limit. Winter in `weather.c` used `&&`
  where `||` was meant; this has no visible effect yet because nothing reads temperature.
- `src/Makefile` hand-listed only `conf.h sysdep.h protos.h` per object, so header edits didn't trigger
  rebuilds. It now uses compiler-generated dependencies (`-MMD -MP`).
- Passwords were stored in plaintext: `CRYPT()` was a no-op because `configure` defined `CIRCLE_CRYPT`
  but `utils.h` tested `HAVE_CRYPT`, and the 12-character field couldn't hold a real hash anyway. They
  are now PBKDF2 hashes (see §7), and old plaintext entries are upgraded at the next login. This
  changed the player-file record size. `util/mudpasswd` builds again (missing include path) and writes
  hashes.
- Per-site connection limit added. `new_descriptor()` (`comm.c`) counts live connections from the
  peer's IP (`descriptor_data.ip_addr`, also restored after copyover) before the DNS lookup and refuses
  extras with a message. Refusals are logged at most once a minute, with a count.
- "You last logged on from ..." printed garbage for **every** player, because it read `nanny()`'s local
  `tmp_store` on a later call than the one that loaded it. The previous host and time are now kept on the
  descriptor (`last_host`, `last_logon`). The line is shown only to existing characters, and the time is
  that of the last save, i.e. when the player last left.
- Zone resets: `reset_zone()` skipped a 100%-chance command 1 time in 100 (`>=` instead of `>`), and a
  skipped command left `last_cmd` set, so the E/G/P commands that depend on it acted on the previously

## 9. Working agreement for agents

1. **Understand before changing.** Read the surrounding code and `grep` for every caller of what you touch.
   This codebase leans on globals and macros, so side effects are common.
2. **Small, focused changes.** One fix or feature per change. Don't reformat or reindent whole files,
   rename the 8.3 files, or run `src/.gsub` (a global sed over all sources).
3. **Match the local style:** CircleMUD/K&R-ish C, 2-space indent in most files, `/* */` comments, C89-compatible
   declarations at the top of blocks. New source files get the same banner header as their neighbours, plus
   `#define __FILE_C__` and the `conf.h` → `sysdep.h` → `protos.h` include order. Add new `.c` files to
   **both** `src/Makefile` and `src/Makefile.in` (just the `OBJFILES` list; the generic `%.o: %.c` rule and
   the generated `.d` files handle the rest).
4. **Definition of done:** builds with **zero warnings** (gcc, and clang if available); the full world boots with
   no new `SYSERR`s; the smoke test passes; the changed behaviour was exercised in-game (or you've explained
   why it couldn't be); help files (`lib/text/help/*.hlp`) are updated for player-visible changes.
5. **Ask first** before you change on-disk formats (pfile structs, world file syntax, data-file formats),
   delete files, change gameplay balance numbers, or add dependencies/tooling.
6. **Never** delete or overwrite `lib/players/*`, `lib/etc/plrmail`, `lib/plrobjs/*` or `lib/house/*`
   unless explicitly asked.
7. **Git:** work on a branch (`fix/…`, `feature/…`, `docs/…`). Commit messages use
   `type(scope): imperative summary` (types: `feat`, `fix`, `refactor`, `docs`, `chore`; scope = module,
   e.g. `fix(mobact): free correct node in FreeHates`), with a body that explains *why*. Don't push or open
   PRs unless asked.
8. When you finish, report: what changed, how it was verified (warning count, boot log, smoke-test
   output), and any follow-ups or doc inaccuracies you found.
