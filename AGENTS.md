# AGENTS.md — DominionMUD

Guidance for AI coding agents (and humans) working on this repository.
Read this file first; it was written by checking the documentation against the
actual source, building it, and booting the server (gcc 13 / Linux, October 2026).

---

## 1. What this project is

- **The Dominion** is a multi-user dungeon (MUD) server written in C between
  1993 and 1998 by Sean Mountcastle (in-game "Glasgian"), Kevin Huff and John Olvey.
  It was recovered from a backup in 2015 and patched to build on Mac OS X 10.10.
- It is a heavily modified **CircleMUD 3.0** (itself derived from **DikuMUD**).
  It also includes **Merc-style MOBprograms** (`mobprog.c`, `mobcmd.c`), an
  OLC (on-line creation) editor (`creation.c`, `olc.c`), copyover (hot reboot),
  data-driven races/religions/guilds/experience tables, and a partial ASCII player-file system.
- Upstream remote: `https://github.com/sean/dominionmud` (branch `master`, 4 commits from 2015).
- **License:** `LICENSE.md` (Dominion license + CircleMUD + DikuMUD licenses). Keep every
  existing copyright/credit header, never remove the CircleMUD/DikuMUD credits, and
  leave the in-game `credits` text (`lib/text/credits`) attributing the original authors.

Most CircleMUD 3.0 knowledge applies directly. When the CircleMUD idiom and this
file disagree, the **source code wins**.

## 2. Source of truth: read this before trusting documentation; source code is always authoritative

Rules for agents:
- **Verify any API, macro or file name in the source** (`grep`) before using it. Never copy a
  code sample from `DOCS/` or `SPECIFICATION/` without checking it.
- **Search with `grep -a`** (or `LC_ALL=C grep`). `act_info.c` contains raw CP437 bytes (0xB2, used for
  bar graphics), so a plain `grep` in a UTF-8 locale calls it a "binary file" and hides matches.
  For example, `sort_commands()` is defined there. Keep those bytes as they are when editing.
- If you find a doc error while working in an area, fix it or flag it in your summary.
  Don't do big doc rewrites unless asked.
- Authoritative in-repo references are the code itself, especially `structs.h`, `utils.h`,
  `interpre.c`, `spells.h`, `spell_pa.c`, `db.h` and the comments at the top of each `lib/data/*` file.

## 4. Build, run and smoke-test

### Build
```sh
make                 # from repo root → builds bin/dominion (via src/Makefile)
cd src && make utils # optional: autowiz listrent purgeplay showplay sign split
make clean
```
- `mkdir -p bin` first on a fresh checkout if needed. `bin/dominion` is gitignored.
- The committed `src/Makefile` and `src/conf.h` are **configure outputs** (from a 2015 macOS run).
  Edit `Makefile.in` / `conf.h.in` too when you change them, or both drift. Running `./configure`
  regenerates them. Don't commit platform-specific regenerated output without saying so.
- **Do not run `make realclean`**: it deletes `lib/etc/players` and `lib/etc/plrmail` (player data).
- **Baseline (gcc 13.3, Linux x86-64): builds and links, exit 0, ~520 warnings.** By flag: about 228
  `-Wformat-overflow`, 171 `-Wrestrict` (mostly `sprintf(buf, "%s...", buf, ...)`), 75 `-Wunused-result`,
  and a few serious ones (§8). **A change must not add new warnings.** Compare the count before and after:
  ```sh
  cd src && make clean >/dev/null && make 2>&1 | grep -c 'warning:'
  ```

### Run
Run from the **repo root** (the default data dir is the relative path `lib`):
```sh
./bin/dominion [-m] [-q] [-r N] [-s] [-d libdir] [port]   # default port 8400
```
- `-m` mini-MUD (loads `index.mini` files, no rent check): fastest for testing
- `-q` quick boot (skip rent check) · `-s` no special procedures · `-r N` restrict new players
- `-c` syntax-check mode: **currently segfaults** (see §8, `parse_fuzzy_mob`)
- `-C<fd>` is internal (copyover re-exec)
- Logs go to stderr. On a healthy boot you get a run of `Resetting <zone>` lines and then
  `No connections.  Going to sleep.` The full world boot currently logs about 7 pre-existing `SYSERR`s
  (`Char is already equipped`, one bad zone command). Those are baseline, not regressions.
- `bin/nightrun.sh` (csh autorun loop) and `bin/automain.sh` are 1990s scripts. They expect a
  directory named `DominionMUD`, `lib/logs/` and a `debug/` dir. Treat them as historical, not as the dev workflow.

### Smoke test (do this after any change that touches runtime code or data)
```sh
./bin/dominion -q 8400 > /tmp/syslog 2>&1 &
sleep 5; grep -c SYSERR /tmp/syslog; tail -2 /tmp/syslog
python3 - <<'EOF'
import socket, time
s = socket.create_connection(("127.0.0.1", 8400)); s.settimeout(2)
def rd():
    out = b""
    try:
        while (d := s.recv(4096)): out += d
    except Exception: pass
    return out.decode("latin1")
print(rd()[-400:])
for line in ["n", "Testplayer"]:           # color prompt, then a new name
    s.sendall((line + "\r\n").encode()); time.sleep(0.5); print(rd()[-400:])
EOF
pkill dominion
```
Extend the script (password, race selection, commands) to exercise the feature you changed.
For combat, spells or saves, log in with a test character and use the actual commands.
**There is no automated test suite.** Proposing a small harness (e.g. a Python
telnet-script runner) is welcome. Ask before adding a framework.

Use `-g -O0` and/or `-fsanitize=address,undefined` (add them to `MYFLAGS` locally) plus `gdb` when debugging crashes.

## 5. How the code is put together (real patterns)

**Command handlers**
```c
ACMD(do_foo);                                   /* 1. prototype near top of interpre.c */
{ "foo", POS_RESTING, do_foo, 0, SCMD_FOO },    /* 2. row in cmd_info[] in interpre.c */
ACMD(do_foo) { ... }                            /* 3. body in the matching act_*.c */
```
- `cmd_info[]` row = `{ name, minimum_position, function, minimum_level, subcmd }`.
  `"RESERVED"` must stay first, the direction commands next, and `"\n"` last. The order of the main
  list matters for abbreviation matching (first prefix match wins), so put a new command where its
  abbreviations behave sensibly. `sort_commands()` builds a sorted index for display only.
- `SCMD_*` sub-command constants live in `interpre.h`. One function often serves several commands.
- Parse arguments with `one_argument()`, `two_arguments()`, `half_chop()`, `skip_spaces()`.

**Output and logging**
- `send_to_char(char *msg, struct char_data *ch)`: note the **message-first** order (CircleMUD 3.0,
  not tbaMUD). Not printf-style: format into a buffer first.
- `act(str, hide_invis, ch, obj, vict_obj, TO_CHAR|TO_VICT|TO_ROOM|TO_NOTVICT)` with `$n $N $e $m $s $p` codes.
- Global scratch buffers `buf`, `buf1`, `buf2`, `arg` (`MAX_STRING_LENGTH` = 64 KB) are shared by
  everything. Don't hold data in them across calls that might also use them. In new code, prefer
  local buffers and `snprintf`. Never `sprintf(buf, "%s...", buf)` (overlapping, undefined behavior).
- `log()` is a macro for `mud_log()`. Use `mudlog(msg, BRF|NRM|CMP, level, TRUE)` for messages
  visible to immortals. Prefix real errors with `SYSERR:`.
- Colour via `CC*` macros in `screen.h` (`CCRED(ch, C_NRM)`, `CCNRM(...)`).

**World objects and memory**
- Characters and objects live on global linked lists (`character_list`, `object_list`) plus
  room/container/inventory lists. Move them only with `handler.c` functions (`char_to_room`/`char_from_room`,
  `obj_to_char`, `obj_to_room`, `equip_char`/`unequip_char`). Destroy them only with `extract_char` / `extract_obj`.
- Rooms are an array `world[]` indexed by **rnum**. Files and builders use **vnum**. Convert with
  `real_room()`, `real_mobile()`, `real_object()`. Mixing them up is the classic bug.
- Allocation uses `CREATE(ptr, type, n)` / `RECREATE` and `str_dup`.

**Spells and skills** (CircleMUD 3.0 design)
1. `#define SPELL_FOO n` in `spells.h` (spells 51…`MAX_SPELLS` 1200, skills to `MAX_SKILLS` 1700).
2. `spello(SPELL_FOO, max_mana, min_mana, mana_change, min_pos, targets, violent, routines)` in
   `mag_assign_spells()` (`spell_pa.c`). Routines are `MAG_DAMAGE | MAG_AFFECTS | ...`.
3. Implement the effect in the matching `mag_*()` switch in `magic.c` (`mag_damage`, `mag_affects`, ...),
   or as a manual `ASPELL(spell_foo)` in `spells.c` for unusual spells.
4. Add the name in the spell names table and the guild/class levels (see `spell_pa.c` / `guild.c`), plus a help entry in `lib/text/help/help.hlp`.

**Special procedures:** `SPECIAL(name)` in `spec_pro.c`, attached to mob, obj or room vnums in `spec_ass.c`.

**Timing:** `structs.h` `OPT_USEC 100000` gives 10 passes/sec. `PULSE_VIOLENCE` = 2 s, `PULSE_ZONE`/`PULSE_MOBILE` = 10 s, etc.

**Levels:** `MAX_LEVEL 50`. `LVL_IMMORT` 43 … `LVL_IMPL` 49, `LVL_CREATOR` 50. These are macros
like `MAX_LEVEL-7`, so wrap them in parentheses when you do arithmetic with them.

## 6. Data files

- `lib/data/{races,religions,guilds,exp_table,attributes}`: each file starts with a comment header
  that defines its format. Read it before editing. Parsers are in `race.c` (`parse_races`, `parse_experience`),
  `religion.c` and `guild.c`. Races are limited to 62 selector letters. `exp_table` needs one row per level up to `MAX_LEVEL`.
  `lib/etc/guilds` and `lib/data/guilds` are duplicates. Check `GUILD_FILE` in `db.h` (`data/guilds`)
  before deciding which one is live.
- World files use the standard CircleMUD 3.0 formats with Dominion extensions (races on mobs, "fuzzy" mobs,
  `>in_file_prog`). Add new zone files to the relevant `index` (and `index.mini` if they're needed in mini mode).
- MOBprograms (`lib/prog/*.prg`) use Merc 2.x syntax: `>greet_prog`, `>rand_prog`, `>speech_prog`,
  `>fight_prog`, `if ... endif`, `mpecho`, etc. `lib/prog/template.prg` documents the triggers.
- OLC (`creation.c`) rewrites world files in place. If you hand-edit world files, keep the exact format
  OLC writes (tildes, `S` terminators, `$` at EOF) or the next OLC save may corrupt them.
- After any data change, boot the full world (not just `-m`) and compare the `SYSERR` count with the baseline.

## 7. Persistence (be careful: this is player data)

There are **two player-save systems**:
1. **Live system (CircleMUD binary):** `lib/etc/players` is an array of raw `struct char_file_u` records
   written with `fwrite` (`db.c` `save_char`/`load_char`, `char_to_store`/`store_to_char`). The login
   path (`interpre.c` nanny, `comm.c` copyover) uses this one. **Any change to `struct char_file_u` or
   to the types or sizes of anything inside it (`structs.h`) silently corrupts existing player files**,
   and the layout also depends on compiler and ABI (32- vs 64-bit). Never change it without an explicit,
   agreed migration plan.
2. **New ASCII system (partial, unfinished):** `save.c` `save_char_obj`/`load_char_obj`/`fread_char` write
   `lib/players/<A-E|F-J|K-O|P-T|U-Z>/<Name>` with key/value lines. Only the `save` command calls it,
   `lib/players/` doesn't exist, and nothing loads from it at login. Finishing this migration is listed
   in `TODO.md` ("/ Started").

Object rent and crash files live in `lib/plrobjs` (`objsave.c`). Mail is in `lib/etc/plrmail` (binary).
Gitignored runtime files: `lib/etc/players`, `lib/etc/plrmail`, `lib/etc/mudtime`, `*.objs`, `*.alias`.

## 8. Known issues (verified October 2026; good starter tasks)

Security
- **Passwords are stored in plaintext.** `utils.h` only uses `crypt()` when `HAVE_CRYPT` is defined, but
  `configure`/`conf.h` define `CIRCLE_CRYPT` instead, so `CRYPT(a,b)` expands to `(a)`. Fixing this changes
  how stored passwords are compared, so plan a migration path. Don't just flip the macro.
- `creation.c:1098` and `shop.c:505` pass non-literal format strings to printf-family functions (`-Wformat-security`).
- Widespread unbounded `sprintf`/`strcpy` into fixed buffers (the hundreds of `-Wformat-overflow` warnings).

Crashes and undefined behavior
- `db.c:1141` `parse_fuzzy_mob()` indexes `races[i]` with the **mob prototype index** instead of the mob's race
  (`GET_RACE(mob_proto + i)`). This reads past the race table, so fuzzy-mob HP is garbage in normal boots and
  `dominion -c` segfaults.
- `db.c:1379-1380` `memset(..., sizeof(struct index_data *))` / `sizeof(struct char_data *)` uses the pointer size
  instead of the struct size, so the prototypes are not actually zeroed.
- `mobact.c:297-315` `FreeHates`/`FreeFears` free `n` (the *next* node) instead of `k`. This leaks the head,
  double-frees, and uses freed memory.
- `save.c:1377` `rent_adjust()` reads an uninitialised `struct rent_info rent` (the initialiser is commented out).
- `save.c:635-660, 852, 921-922, 1173` store pointers in `int` fields (`(int) &def_sdesc`). That truncates on
  64-bit systems and crashes the ASCII loader whenever it falls back to a default string.
- `-Wmisleading-indentation` at `magic.c:143,161` and `act_item.c:1609` should be checked for real logic bugs.

Housekeeping
- `castle.c` and `opinion.c` aren't built. `opinion.c`'s functions were partly moved into `mobact.c`.
- Generated `src/Makefile`/`conf.h` are committed and macOS-flavoured. The legacy non-Unix Makefiles and
  `conf.h.*` are unmaintained.
- `TODO.md` (accounts system, skills/spells in text files), `lib/data/README`, and the 1990s player
  reports in `lib/misc/{bugs,ideas,typos,todo}` are the historical backlog.
- `DOCS/` and `SPECIFICATION/` are untracked and inaccurate (§2).

## 9. Working agreement for agents

1. **Understand before changing.** Read the surrounding code and `grep` for every caller of what you touch.
   This codebase leans on globals and macros, so side effects are common.
2. **Small, focused changes.** One fix or feature per change. Don't reformat or reindent whole files,
   rename the 8.3 files, or run `src/.gsub` (a global sed over all sources).
3. **Match the local style:** CircleMUD/K&R-ish C, 2-space indent in most files, `/* */` comments, C89-compatible
   declarations at the top of blocks. New source files get the same banner header as their neighbours, plus
   `#define __FILE_C__` and the `conf.h` → `sysdep.h` → `protos.h` include order. Add new `.c` files to
   **both** `src/Makefile` and `src/Makefile.in` (OBJFILES and a dependency rule).
4. **Definition of done:** builds with **no new warnings** compared to baseline; the full world boots with
   no new `SYSERR`s; the smoke test passes; the changed behaviour was exercised in-game (or you've explained
   why it couldn't be); help files (`lib/text/help/*.hlp`) are updated for player-visible changes.
5. **Ask first** before you change on-disk formats (pfile structs, world file syntax, data-file formats),
   delete files, change gameplay balance numbers, or add dependencies/tooling.
6. **Never** delete or overwrite `lib/etc/players`, `lib/etc/plrmail`, `lib/plrobjs/*` or `lib/house/*`
   unless explicitly asked.
7. **Git:** work on a branch (`fix/…`, `feature/…`, `docs/…`). Commit messages use
   `type(scope): imperative summary` (types: `feat`, `fix`, `refactor`, `docs`, `chore`; scope = module,
   e.g. `fix(mobact): free correct node in FreeHates`), with a body that explains *why*. Don't push or open
   PRs unless asked.
8. When you finish, report: what changed, how it was verified (warning count, boot log, smoke-test
   output), and any follow-ups or doc inaccuracies you found.

## 10. Glossary

vnum/rnum — virtual (file) number vs. real (array) index · mob — NPC · pfile — player file ·
rent — storing a player's items while offline · zone reset — periodic repopulation from `.zon` commands ·
spec proc — C function attached to a mob/obj/room · MOBprog — script attached to a mob ·
OLC — online creation (in-game building) · copyover — hot reboot that keeps connections open ·
immortal/imm — staff character (level ≥ 43) · Glasgian — Sean's in-game name.
